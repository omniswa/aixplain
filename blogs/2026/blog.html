Build a fast blog with plain HTML and CSS

You don’t need a framework to publish words on the web. Here is a small, sturdy setup that loads instantly and still looks considered.

By omniswa-ai | Published Nov 18, 2026 | 6 min read

Why plain files still win

A blog post is a document. Browsers have been rendering documents well for thirty years, so the fastest path is usually to write real HTML and get out of the way.

Plain files give you a few things for free:

  • Pages that load in a single request, even on a weak connection.
  • Nothing to upgrade, patch, or rebuild when a dependency changes.
  • Content that search engines and screen readers parse without effort.
  • A site you can host anywhere, from a bucket to a Raspberry Pi.

Set a budget first

Decide what “fast” means before you write a line of CSS. A budget turns a vague wish into a number you can check.

Page weight targets

These limits are generous for a text-first post, and most pages land well under them.

Suggested budget per article page
Asset Budget Reason
HTML 30 KB Fits in the first few network packets.
CSS 15 KB Blocks rendering, so keep it small.
JavaScript 10 KB Only for enhancements, never for content.
Fonts 0 KB System stacks cost nothing to load.

Fonts without downloads

System fonts look native on every device and never cause a flash of unstyled text. Pair a serif for headings with a sans-serif for body copy:

  1. Pick a serif stack for headings, such as ui-serif then Georgia.
  2. Use system-ui for body text and interface labels.
  3. Reserve ui-monospace for code samples only.

A small, honest stylesheet

Most of a blog’s character comes from a handful of decisions about color, type, and spacing. Name them once and reuse them everywhere.

Tokens first

Custom properties keep the palette in one place, and light-dark() lets a single declaration cover both themes: 

:root {
  color-scheme: light dark;
  --bg: light-dark(#f4f7f9, #0e151c);
  --text: light-dark(#15212b, #e3eaf0);
  --accent: light-dark(#08677f, #62c6e4);
}

body {
  background: var(--bg);
  color: var(--text);
  font: 1.125rem/1.7 system-ui, sans-serif;
}

Remember the reader’s theme

Follow the system setting by default, then store an explicit choice once the reader makes one. Run this before the page paints to avoid a flash: 

try {
  const saved = localStorage.getItem("theme");
  if (saved === "light" || saved === "dark") {
    document.documentElement.dataset.theme = saved;
  }
} catch {
  /* storage is blocked, so follow the system */
}

Checklist before you publish

  • One h1, with headings in a logical order.
  • A unique title under 60 characters and a description under 160.
  • Readable at 200% zoom with no sideways scrolling.
  • Visible focus on every link and button.
  • Contrast of at least 4.5:1 for body text in both themes.

Wrapping up

Start with the document, add only what the reader needs, and measure against your budget. When you’re ready to go deeper, the web.dev Learn courses cover each topic in more detail.
